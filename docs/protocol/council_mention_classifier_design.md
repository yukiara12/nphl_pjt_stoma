# 議事録「基準額言及」判定ルールの設計と評価

## 結論

- 推奨ルール：同一発言内で、ストーマ語（ストーマ/ストマ/オストメイト/蓄便袋/蓄尿袋/人工肛門/人工膀胱/人工ぼうこう）の前後150文字以内に上限額語があれば A。ただし両語の間に「トイレ/備蓄/避難/便座/洗浄」が挟まるペアは数えない。会議単位では、会議内にAが1件以上あれば「基準額に言及した会議」とする。
- ラベル付きサンプル（117会議・303発言）での性能：発言単位 precision 0.77 / recall 0.89、会議単位 precision 0.72 / recall 1.00。
- 上限額語：基準額、上限額、給付額、支給額、公費負担、自己負担、給付上限、基準価格、単価、増額、引き上げ、引上げ、引き上、見直し、実勢価格、価格の上昇、価格高騰、価格の高騰、限度額、助成額、補助額、値上、物価高、価格が上昇、価格上昇、負担額、月額
- 実装：`scripts/04_classify_council_mentions.py`（出力 `data/raw/council_minutes/stoma_mentions_classified.csv`）

## サイト仕様について分かったこと（重要）

- ssp.kaigiroku.net の画面は、内部で JSON API（`https://ssp.kaigiroku.net/dnp/search/...` への POST）を呼んでいる。Playwright を使わなくても、通常の HTTP POST で同じ結果が得られる。
  - tenant 番号：`/tenant/{tenant}/js/tenant.js` に `dnp.params.tenant_id = N` と書かれている
  - 検索：`minute_searches/search`（`function=all` で年ごとの件数〔facet〕、`function=year&fq_view_year=YYYY` でその年のヒット会議と発言ID〔minute_id〕・スニペット）
  - 本文：`minutes/get_minute`（council_id, schedule_id を指定すると、会議の全発言が発言者・本文つきで返る。1会議あたり数百KB）
- 検索結果の画面は初期状態では最新年しか表示しない（年ごとのタブ切替）。02_search_council_stoma.py の details は各テナント・各キーワードの「最新年のヒットだけ」を取っていたことになる。ページ送りではなく年の切替が「全件取得」の単位で、1年分は1回のリクエストで全件返る（立川市「トイレ」2023年で138件が1回で返ることを確認）。
- results CSV の hit_count（例：立川市オストメイト194）は会議数ではなく発言数（numFound）。
- 複数語検索：スペース区切り（半角・全角どちらも）は AND として扱われ、発言単位の AND になる（北九州市「ストーマ 上限額」→ 立山議員・局長答弁の発言IDのみ返った）。OR は演算子として解釈されず、「OR」という語として扱われる。0件のときは facet が返らない。
- 目次・名簿もひとつの「発言」として返る（議事日程に「オストメイト」等が載ると拾われる）。
- 日付は会議名（元号年・月）と日程名（「09月24日－02号」）から組み立てる必要がある。全角数字・全角スペース・「元年」が混在。「議会報」「参考資料」など日程名に日付のない会議があり、年度が空欄または月単位の近似になる。

## サンプリング方法

- 母集団：`stoma_search_details.csv` のうち MinuteView URL がある ssp テナントの会議（重複除去後）。
- 固定枠：北九州市（R8.6 の2会議を含む）、さいたま市、松山市の全会議（計13会議）。
- 無作為枠：キーワード別に、オストメイト45・ストーマ35・蓄便袋12・蓄尿袋12会議（1テナント1会議、乱数シード20261114）。
- 合計117会議・103テナント・303発言。各会議の本文を get_minute で取得し、キーワードを含む発言をすべて抜き出して人手で読んでラベルを付けた（ラベル付けは1名。判定はClaudeによる）。
- 注意：details CSV 自体が最新年に偏っているため、サンプルも2023〜2026年度が多い（2025年度が82発言で最多）。

## ラベル定義と分布

| ラベル | 内容 | 発言数 |
|---|---|---|
| A | 基準額・上限額・給付額の水準、その引き上げや据え置き、金額の提示 | 66 |
| B | 日常生活用具給付だが基準額以外（品目・付属品、一時的ストーマ、申請手続、自己負担割合、給付件数・決算額） | 77 |
| C | オストメイト対応トイレ等の設備 | 90 |
| D | 災害備蓄・避難所・装具保管・トイレカー | 46 |
| E | その他（講習会・啓発、医療一般、目次・名簿、ごみ袋・下水道料金など） | 24 |

- 会議単位：A を含む会議は117会議中26会議。
- 抽出枠別の A 会議数：オストメイト 5/45、ストーマ 7/35、蓄便袋 4/12、蓄尿袋 3/12、固定枠 7/13。オストメイトは9割近くが A 以外（C・D が中心）。
- 判定の線引き：基準額の金額を述べるだけの発言（例：「基準額は月額8,858円」）も A とした。「基準額の範囲内で付属品をやりくり」のように品目の話で基準額に触れるだけのものは B とした。1割負担の廃止など自己負担割合の話は B。

## ルール比較

サンプル内の比較（P=precision, R=recall）。会議単位は「会議内に予測Aが1件以上」と「正解Aが1件以上」を比べた。

| ルール | 発言 P | 発言 R | 会議 P | 会議 R |
|---|---|---|---|---|
| R0 キーワードを含む全発言 | 0.22 | 1.00 | 0.22 | 1.00 |
| R1 同一発言内の共起（基本語17語） | 0.58 | 0.85 | 0.48 | 1.00 |
| R1x 同一発言内の共起（拡張語） | 0.59 | 0.92 | 0.46 | 1.00 |
| R1s 共起（拡張語、オストメイト除く） | 0.67 | 0.86 | 0.57 | 1.00 |
| R1g 共起（強い語のみ：基準額・上限額・給付額・支給額・給付上限・基準価格・限度額・助成額・補助額・公費負担） | 0.74 | 0.80 | 0.64 | 0.96 |
| R2 窓50（拡張語） | 0.82 | 0.74 | 0.83 | 0.96 |
| R2 窓100（拡張語） | 0.77 | 0.85 | 0.72 | 1.00 |
| R2 窓150（拡張語） | 0.72 | 0.91 | 0.65 | 1.00 |
| R2 窓300（拡張語） | 0.70 | 0.92 | 0.62 | 1.00 |
| R3 窓100（強い語のみ） | 0.89 | 0.76 | 0.86 | 0.96 |
| R4 AND検索相当（ストーマ・蓄便袋・蓄尿袋 × 基準額・上限額・限度額・給付額） | 0.84 | 0.74 | 0.81 | 0.96 |
| V2 窓100（拡張語＋月額、間にトイレ等で除外） | 0.80 | 0.83 | 0.79 | 1.00 |
| **V2 窓150（拡張語＋月額、間にトイレ等で除外）＝推奨** | **0.77** | **0.89** | **0.72** | **1.00** |
| V1y 窓150（拡張語＋月額＋「〇円」） | 0.64 | 0.95 | 0.53 | 1.00 |

推奨の理由：

- 会議単位の recall が1.00で、その中では precision が高い部類に入る。窓100版は precision が高いが、発言単位の recall が0.83に下がる。基準額の議論は1会議で何度もやり取りされることが多く、1発言を落としても会議単位では救われやすい。ただ、1発言しか言及のない会議（さいたま市 R6.6 保健福祉委員会など）もあるため、窓は少し広めの150にした。
- オストメイトを語彙から外す案（R1s）は、北九州市のように「オストメイトの方が使用するストーマ装具の公費負担上限額」と書かれる発言は救えるが、「オストメイトの給付基準額」のような言い回しを落とす。窓を使えばトイレの誤検出は大きく減るので、オストメイトも語彙に残した。
- 金額表現（「〇円」）を上限額語に加えると recall は上がるが、トイレ改修費・決算額による誤検出が増える。
- AND検索（R4）は precision は高いが recall が低く、ストーマ語×上限額語の組み合わせ数だけ検索が必要になる。前処理（事前ふるい）として使うなら、次の使い方に限るのがよい（推測）：テナントごとに「ストーマ 基準額」など数本の AND 検索を `function=all` で投げ、年ごとの件数だけを見て、本文取得の優先順位を決める。全件判定の代わりにはならない。

トレードオフ：会議単位では、約3割（サンプルで36会議中10会議）が A 以外の会議を A と判定する。年度フラグを分析に使う前に、A 判定の会議だけ excerpt を目視で確認する運用を想定している（全件の目視より負担はかなり小さい）。

注意：ルールはラベルを付けた同じサンプルで選んだので、上の数値は楽観的な見積もりである。下の検証5テナント（サンプル外の発言を多く含む）では、A 判定の発言をざっと目視したところ、誤検出の割合はサンプルと同程度（2割弱）だった（概数、厳密なラベル付けはしていない）。

## 代表的な失敗例

誤検出（FP）：

- 「見直し」の多義性：「交通バリアフリー法のガイドラインの見直し」（多久市 H14、松山市 H14）、「設置基準を見直し、オストメイトトイレの設置を標準に」（北九州市 R7.12）、「備蓄量の見直し」（袖ケ浦市 H23）。「トイレ」が両語の間にないと除外できない。
- 制度説明での「自己負担」「公費負担」「基準単価」：申請手続（十和田市「１割の自己負担金額を支払う」）、事業概要の説明（佐久市・塩尻市）、公費負担に占める割合（鶴ヶ島市）。
- 予算・決算の説明で、別項目の「増額」がストーマの近くに来る（摂津市 H18）。岩美町のトイレ改修費の「増額」のように、間に「トイレ」が入るものは除外語で落ちる。
- 付属品の話の中で基準額の仕組みに触れる（立川市 H27「定められた月額の基準額内で」）。

見逃し（FN）：

- 上限額語のない追加質問：「三田市と尼崎市で4,000円ほどの差がある」（尼崎市）、「消化器系は8,850円ですが…1,150円不足」（十和田市）、「額は変更はございません」（尾道市）、「国から移行されたもので、かなり長い間そのまま」（釜石市）。
- 除外語による見逃し：北九州市 R8.6.9 立山議員の再質問「個人でストーマ装具を備蓄するためにも、公費負担上限額の引上げは不可欠」は、間に「備蓄」が入るため A にならない（同じ会議の他発言で会議単位は A）。
- いずれも同じ会議内に A と判定される発言があり、サンプルでは会議単位の見逃しは0件だった。1往復だけの短いやり取りで金額しか言わない会議では落ちる可能性がある。

## 全件実行の所要時間（推定値）

- 検証5テナントで146会議・計406秒（1会議あたり約2.8秒、検索リクエスト込み、リクエスト間隔1.5秒）。
- 既存 results CSV のヒット数（発言数）合計は約8,700件。検証5テナントの「会議数/ヒット発言数」比は約0.36なので、本文取得が必要な会議は約3,100件（02 のタイムアウト・接続エラー約400件分を加えると多めに見て4,000件程度）。
- 3,100〜4,000会議 × 2.8秒 ≒ 2.5〜3.1時間。ヒットの少ないテナントも1件あたり5〜10リクエストはかかるので、506テナント分で約1時間を加え、全体で約3.5〜4.5時間（推定値）。
- resume は `stoma_mentions_progress.csv` で管理しているので、中断しても再実行で続きから再開できる。エラーになったテナントは status に error が入り、次回の実行で再試行される。

## 実行上の注意

- リクエスト間隔は既定で1.5秒（`--delay`）。検証中にブロックやエラー応答はなかった。
- get_minute は1会議で数百KB〜1MBを返すため、全件実行では数GB規模の通信になる（推定）。本文は保存しておらず、excerpt（300字）のみ CSV に残す。
- オストメイトのヒットが多いテナント（立川市194件など）は会議数が増えて時間がかかる。
- 年度フラグを作る際は、`meeting_has_A=1` の会議を年度で集計する。fiscal_year 空欄の行は手で補う。
