# 議会議事録ストーマ関連キーワード検索：プロセス記録

作成日: 2026-09-24
担当: Niidome

## 目的

全国の市区町村議会議事録において、ストーマ装具の給付制度に関する議論がどの程度行われているかを定量的に把握する。議会での言及頻度と基準額の増額実績の関連を探り、PJ2（自治体ヒアリング）の対象選定に活用する。

## 使用データ・ツール

- 議事録検索システム一覧: `data/master/council_search_systems.csv`（895自治体、1,058 URL）
  - app-mints.com/kaigiroku/ から収集（スクリプト01）
  - システム種別: kaigiroku_ssp(503), dbsr(158), kensakusystem(121), gijiroku_com(102), other(78)
- Playwright（Chromiumヘッドレス）による自動検索
- Python 3.9

## プロセス

### Step 1: 議事録検索URL収集（スクリプト01）

`code/collection/01_collect_council_urls.py`

app-mints.com/kaigiroku/ のリンク集から、全国自治体の議事録検索システムURLを収集した。895自治体・1,058 URLが取得でき、システム種別ごとに分類した。

### Step 2: ssp.kaigiroku.net 503テナント自動検索（スクリプト02）

`code/collection/02_search_council_stoma.py`

最も数が多いkaigiroku_ssp系（503テナント）を対象に、Playwrightでブラウザを自動操作してキーワード検索を実行した。

#### 検索キーワード（4つ）
- ストーマ
- オストメイト
- 蓄便袋（＝消化器系ストーマ装具の行政上の正式名称）
- 蓄尿袋（＝尿路系ストーマ装具の行政上の正式名称）

#### 実行上の工夫と試行錯誤

**1. 途中保存とレジューム機能の追加**

当初のスクリプトは全結果をメモリに保持し、最後に一括でCSV書き出す設計だった。503テナント×4キーワードの実行には数時間かかるため、途中でプロセスが落ちるとすべての進捗が失われる問題があった。

対策として以下を実装した：
- テナントごとにCSVへ追記（`append_results()`）
- 起動時に既存CSVから完了済みテナントを読み込み、スキップ（`load_completed_tenants()`）
- `--fresh` フラグで既存結果を無視してゼロからやり直すオプション

これにより、ネットワーク障害やマシンスリープで中断しても、同じコマンドを再実行するだけで続きから再開できるようになった。

**2. 詳細取得（議事録URL）の方式変更**

最初の実装では、検索結果ページ内の各議事録リンクをPlaywrightでクリック→ページ遷移→URL取得→戻る、という方式で議事録URLを取得していた。しかし：
- 1リンクあたり約4秒（遷移2秒+戻り2秒）かかり、ヒットが多いテナントでは非常に遅い
- JavaScriptで遷移する場合、URLが正しく取得できないケースがあった
- 結果として1テナントあたり約4分、全体で33時間以上の見積もりになった

対策として、DOMから直接URLを読み取る方式に変更した：
```python
# 3段階フォールバック
# 1) href属性を直接読む
href = link_el.get_attribute('href')
# 2) onclick属性からcouncil_id/schedule_idを抽出してURL構築
onclick = link_el.get_attribute('onclick')
# 3) JavaScriptで解決されたhrefを取得
resolved = link_el.evaluate("el => el.href || ''")
```
これによりクリック遷移が不要になり、詳細取得ありでも大幅に高速化できる。

**3. 実行戦略：2段階に分離**

最終的に以下の2段階で実行した：
1. `--no-details` で全503テナントのヒット件数のみを高速取得（約3時間）
2. ヒットのあったテナントのみ、改修済みスクリプトでdetails付き再実行（未実施、今後の課題）

**4. エラーの傾向**

503テナント中、約85テナントで全キーワードがエラー（`net::ERR_` や `Timeout`）だった。原因は：
- 一部のテナントがHTTPS対応していない（`net::ERR_`）
- サーバーの応答が遅い地域がある（Timeout）
- 沖縄県のテナントは全滅だった（ネットワーク経路の問題の可能性）

エラーとなったテナントは `hit_count = -1` として記録しており、手動での再確認が必要。

### Step 3: 統合DB構築（スクリプト03）

`code/collection/03_build_database.py`

全国1,918市区町村のマスターに対して、以下を統合した：
- 都道府県別基準額（白書2023）
- 議事録検索システムURL
- キーワード検索結果（ヒット件数）
- 個別自治体の確認済み基準額

### Step 4: 基準額のWeb調査（Claude Code エージェント並列実行）

議会で「ストーマ」を5回以上言及していた145自治体のうち、上位32自治体を4グループに分け、Claude Codeのサブエージェント機能で並列にWeb調査を実施した。

調査方法：
- 各自治体の例規集（g-reiki.net等）で実施要綱の別表を確認
- 公式サイトの「日常生活用具の給付」ページでPDF・一覧表を確認
- 検索キーワード：「〇〇市 ストーマ 基準額」「〇〇市 日常生活用具 蓄便袋」等

32自治体中26自治体で基準額を確認できた（確認率81%）。残り6自治体は公式サイトに基準額が公開されておらず、電話確認が必要。

## 所見・示唆

- 増額自治体はR7（2025）年の改定に集中しており、近年の全国的な動きを反映している
- 愛川町は議会言及34件で全体2位の多さだが、基準額は8,600円で中央値を下回ったまま。議会での議論が必ずしも制度改善に直結しないケースとして注目に値する
- 鶴岡市（12,600/15,300円）は全国最高水準。R7.6には一時ストーマ造設者への助成も開始しており、先進事例として参考になる
- 「オストメイト」のヒット数はトイレ整備（バリアフリー）の文脈が多く、給付制度の議論に直結するのは「ストーマ」「蓄便袋」「蓄尿袋」のヒット

3. **details付き再実行**: 修正済みのDOM直接読み取り方式で、ヒットのあったテナントの議事録URLを取得
4. **議事録の内容分析**: URLが取得できた議事録について、基準額に関する具体的な発言内容を抽出（質問者・答弁者・発言日の特定）
5. **基準額の経年変化追跡**: MPI-STOREのニュースレター等から増額の動向を補完

## スクリプトの使い方

### 前提条件
```bash
pip install playwright
python -m playwright install chromium
```

### 実行手順
```bash
# 1. 全テナントのヒット件数を取得（約3時間）
python code/collection/02_search_council_stoma.py --no-details

# 中断した場合、同じコマンドで続きから再開
python code/collection/02_search_council_stoma.py --no-details

# テスト実行（最初の5件のみ）
python code/collection/02_search_council_stoma.py --test 5

# 特定テナントのみ実行
python code/collection/02_search_council_stoma.py --tenant shinjuku,muroran

# ゼロからやり直す場合
python code/collection/02_search_council_stoma.py --fresh --no-details
```
